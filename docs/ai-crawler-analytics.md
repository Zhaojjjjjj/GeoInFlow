# AI 爬虫分析与 GEO 运营

GEOInflow 帮助团队把 AI 对网站的访问、内容分布、技术问题与实际引荐访问放在一起观察。日志提供请求证据，内容目录提供已知页面集合，浏览器事件提供访客和业务效果。

这些资料可以支持内容维护和技术排查。抓取、可访问、被搜索系统收录、在回答中引用及获得转化分别需要相应证据。

## 数据需要准备到什么程度

| 数据 | 能回答的问题 | 缺失时的状态 |
| --- | --- | --- |
| 网站 / CDN 访问日志 | 哪些身份声明到达、访问何路径、返回何状态 | 抓取观察缺少输入 |
| 官方范围及核验依据 | 请求来源能得到何种支持 | UA 声明保留，核验未知或未匹配 |
| 来源生效区间与连续性 | 某段时间是否具备可比观察 | 显示缺口、部分或未知覆盖 |
| 内容目录 | 已知内容中有哪些访问记录 | 依赖目录的覆盖分母不可用 |
| 浏览器脚本 | AI 引荐会话、落地页和浏览行为 | 引荐与访客业务指标缺少输入 |
| 事件与目标 | 实际访问是否完成定义的业务动作 | 转化保持未配置或无输入状态 |

手动日志、自动采集和 Cloudflare 的覆盖证明能力不同。手动导入缺少数据，可能表示文件不足；已证明连续观察范围内的零值，才具有对应的零值解释。具体规则见 [来源质量](crawler-control.md#来源质量)。

## 身份、用途和产品形态

目录分别保存平台、产品和请求身份。例如同一厂商可以使用多个不同请求身份，分别对应训练、搜索索引或用户主动请求。

用途筛选包括 AI 训练、AI 搜索、用户触发、传统搜索和其他用途；AI 工作台、个人 Agent 作为产品形态筛选。用途与产品形态存在交集，将两类筛选结果直接相加会重复计数。总量按页面约定的唯一请求总体计算。

“其他爬虫”使用自己的筛选规则，未知和歧义请求另有查看入口。Google-Extended 属于 robots 用途控制项，不产生独立 HTTP 蜘蛛统计。

内置目录覆盖多家国内外平台，运行时以管理员发布版本和网站启用配置为准。新增目录项、官方来源变更和用途调整通过草稿、正反例与发布预览审核，保留稳定 ID 及历史版本。

### 核验状态如何理解

| 证据 | 表示什么 | 解释范围 |
| --- | --- | --- |
| UA 匹配 | 请求声明的标记符合某个身份 | UA 可以被复制，仍需核对来源 |
| 官方范围匹配 | 请求与该身份适用的官方地址快照一致 | 使用归档版本与核验时观测时间 |
| 官方范围未匹配 | 有可用地址，但未匹配适用范围 | 保留独立结果，不直接推断访问动机 |
| 未核验 / 证据缺失 | 当前资料不足以完成该项核验 | 历史缺失继续保留未知 |
| DNS / 可信边缘证据 | 在已支持身份和可信接入下提供额外证明 | 方法、适用对象与字段条件各自记录 |

系统已接入部分官方 DNS 和精确可信边缘证据。通用 HTTP 签名验证器未覆盖全部 Agent 协议，出现 `Signature-Agent` 或签名字段本身不足以标记验证成功。

官方 IP 范围会记录内容版本、最后成功观测、过期与异常变化。当前目录更新不会将旧日志自动改写成新的已核验身份。

## 从页面读取结果

### 抓取总览与 AI 爬虫台账

先选择范围、身份口径和用途，核对请求量、识别身份、趋势、最近访问及响应状态。默认全部已识别声明与官方范围匹配的口径分开，页面可以按实际支持的条件切换。

训练、搜索和用户触发具有不同用途。一次训练型访问不能直接计作某个搜索产品的引荐；同平台多个请求身份共享平台级引荐指标时，平台访客只计一次。

台账适合观察身份变化与频率，异常变化需要结合规则版本、来源是否切换、日志是否迟到或中断一起核对。

### 抓取页面与内容目录

| 结果 | 用途 | 需要同时核对 |
| --- | --- | --- |
| 抓取次数与重复抓取 | 查找高频页面与重复路径 | 相同日期、身份与有效请求范围 |
| 主力蜘蛛与身份数 | 查看哪些已识别身份访问某页 | 自定义与官方映射、历史版本 |
| 目录维度分布 | 观察文档、产品、资讯等目录的访问侧重 | 目录结构与路径对应 |
| 缺少抓取记录的页面 | 检查已知关键内容的观察盲区 | 该模块显示的时间范围、目录完整性与日志覆盖 |
| 最近抓取与新鲜度 | 观察内容更新与访问时间的关系 | 已导入内容元数据，缺失字段保持缺失 |
| 路径与深度观察 | 检查路径层级和估算访问顺序 | 页面标注的观察或估算含义 |

路径层级、日志顺序和估算轨迹不能证明爬虫实际沿链接走过的完整导航路径。目录中的成功响应覆盖，也只证明观察到相应请求与响应。

### HTTP 响应与风险

请求总量、GET / HEAD、304、成功响应、拒绝和服务器错误分别展示。边缘耗时、上游耗时、字节与缓存状态按字段本身的含义统计，并保留有效样本数。

风险发现包括访问受阻、源站错误、突增、覆盖下降、关键页面访问预期、身份范围异常和敏感路径。记录中保留发生窗口、证据与处理状态，运营人员可以备注、暂缓、恢复并追踪复发。

风险判断需要来源连续性和比较依据。日志缺口、处理积压及历史缺证保留为相应限制，避免把这些状态解释为蜘蛛停止访问。

### AI 引荐与转化

AI 搜索引荐从浏览器入口来源识别，结合 UTM 及现有归因规则，查看访客、落地页、浏览量和目标转化。搜索引擎与关键词页面保留传统搜索和 AI 搜索的分类，搜索词缺失、跳转来源、脱敏和不支持分别标注。

部分平台在主机、时间、身份和来源覆盖具备可比性时提供抓取与引荐的关系指标。它们属于关联观察，具体抓取和具体访客之间没有由此建立的因果证明。

## GEO 权重 Beta

GEO 权重描述最近 30 个完整自然日内符合固定政策的已核验 AI 内容访问。当前日视图截至昨日，展示 1 至 10 级的权重及计算依据；已证明完整观察的零值单独表示。输入不足或证据不可用时可以保留空值。

政策固定适用身份、厂商、用途、成功内容请求和去重单元，按搜索、用户触发、训练计算加权活动量。目录中新增身份不会自动扩大计分政策；DNS 或边缘核验也不会自动取得当前计分资格。

权重提供内容被已核验 AI 访问的一个参考，行业校准仍属 Beta 范围。内容目录规模、来源和证据限制需要随结果一起阅读。它与外部搜索排名、引用率、训练收录率和销售收入分别解释。

公式、区间、证据要求及不可变日快照见 [GEO 权重说明](geo-weight.md)。

## 一轮可执行的运营工作

1. 接入并核对浏览器与日志输入，导入实际内容目录，记录所选日期、时区及来源状态。
2. 从 AI 爬虫台账选择重点身份与用途，观察趋势和最近访问。
3. 在抓取页面查看关键内容、重复路径和目录分布，核对缺少记录的页面是否具备可比覆盖。
4. 针对问题检查真实响应、robots、状态码、缓存和内部链接，将技术调整交给对应网站维护者。
5. 调整后保留同一身份和时间定义，继续观察完整窗口，记录来源、内容或规则变更。
6. 查看 AI 引荐落地页和已配置目标的变化，记录观察、可能原因及仍缺少的证据。

内容团队可以据此安排页面维护；技术团队可以定位访问错误和负载；GEO 服务团队可以保留带范围、版本和限制的分析结果，与客户讨论实际行动。

## 策略操作如何落地

robots 和 Nginx 提供草稿或配置导出，由网站维护者核对并部署。robots 的实际遵守取决于访问方；Nginx 配置需要通过对应环境的语法检查及恢复演练。

已支持的 Cloudflare 操作使用独立、仅限目标 Zone 的凭据，依次执行差异预览、权限核对、明确确认、后台执行及远端回读。结果未知时先只读核对，再由有权人员处理。提供方真实套餐、权限、配额和边缘效果需要在实际 Zone 验收。

自动远程执行 Nginx、通用限速能力和外部搜索曝光并未由现有导出或风险提示自动提供。当前控制范围见 [抓取控制](crawler-control.md)。

## 分享、导出与 AI 辅助

分享和导出使用其权限允许的模块及固定范围，保留日期、时区、身份筛选和数据状态。GEO 权重具有独立的私人读取边界，不对公开分享开放。

可选 AI 配置器可以基于有限网站事实生成观察、可能原因、建议和限制。启用它需要自己的模型连接及相应费用；核心爬虫统计继续按确定的数据规则运行。模型收到什么、保存什么以及输出如何核对，见 [AI 配置器](ai.md)。

## 常见解释问题

| 问题 | 解释 |
| --- | --- |
| UA 写着 GPTBot，就能确认来自 OpenAI 吗 | 先查看其来源核验，UA 声明与核验分别保存 |
| 请求增加，能说明收录或引用增加吗 | 需要外部收录与回答证据，再与日志观察对照 |
| 今天没有抓取，说明 AI 停止访问了吗 | 先检查日期、最新数据、采集连续性与积压 |
| 有抓取量，为何 GEO 权重为空 | 计分身份、内容请求、完整观察时长及归档范围证据有更具体要求 |
| AI 工作台与个人 Agent 可以相加吗 | 产品形态与用途存在交集，使用全部总体或明确去重结果 |
| 能自动知道 AI 回答里有没有引用品牌吗 | 当前日志与引荐提供各自观察，回答引用需要单独的引用监测数据 |
